Verify or restore a backup

Verification decrypts the archive, checks every file fingerprint and runs SQLite integrity checks. It does not prove that you remember your vault master password.

Restore on a fresh computer: run MyVault.exe restore --data C:\MyVault-Recovered --input X:\Recovery\myvault.age. A local wizard asks for the backup secret; existing installations are never overwritten.

Make offline access real

Install an official Bitwarden desktop, browser or mobile client. Choose self-hosted and enter your vault URL.

Stay logged in. Logging out, reinstalling or losing local app data can remove offline access. The web vault is not an offline cache; do not assume offline editing or sync.

Automatic backups & retention

Use an independent age recovery key for scheduled backups. The server stores only its public recipient; save the secret key off the server. Scheduled archives remain unverified until checked with that independent key.

Save this key now, outside One Workspace. It will not be retained by the server.

Set hours to 0 to disable scheduling. Retention is an explicit separate action and never deletes unverified archives or the last two verified copies.

Sign in with MyAccounts

Checking sign-in connection…

One Workspace connects this automatically when it starts My Vault. An active vault session opens immediately; an active MyAccounts session skips another account sign-in. A locked vault still asks for its master password.

Your MyAccounts email must be verified and match an existing vault account for its first connection. Create the independent vault account first. No master password is sent to MyAccounts.

Standalone or custom MyAccounts connection

Register this vault address followed by /identity/connect/oidc-signin as the exact callback. Use standard RS256 ID tokens, verified email claims and authorization code with PKCE.

Disabling this connection persists across Workspace starts. Independent sign-in, encrypted recovery and existing client encryption are preserved.

Secure access on this computer

The official client requires HTTPS, including localhost. My Vault creates a unique localhost-only certificate, which is not a certificate authority. Startup never changes Windows trust.

Open secure local vault ↗

This explicit action adds the local certificate to the current Windows user’s trusted store. Do not bypass browser warnings. Other devices use your dedicated publicly trusted HTTPS address.

Independent accounts

Your vault email, master password and MFA work independently of MyAccounts. Account creation is closed by default.

Create the selected account locally ↗

The user enters their master password only in the compatible vault client. This companion never asks for it.

Secure remote access

Use a dedicated HTTPS hostname, separate from the other Workspace apps, to isolate vault keys from their browser storage. The engine always binds to loopback.

Point a trusted HTTPS reverse proxy or dedicated Cloudflare tunnel hostname at the vault's loopback listener. Do not proxy its local management port or expose plain HTTP.

Keep an independent route: run MyVault.exe directly with the same data folder if Workspace or MyAccounts is unavailable. Only one instance can own that folder.
